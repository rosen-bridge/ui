# ui-kit rules for AI agents

Follow these rules exactly in `@rosen-bridge/ui-kit`; ask before deviating from any of them.

## Workflow

- Ask before deleting, renaming or replacing an existing component, file or API.
- Don't stage or commit; the developer does.
- After a change, run `npx biome check`, `npx tsc` and `npm run build` in `packages/ui-kit`.
- Add a changeset in `.changeset/` per change: `minor` for a new component or feature, `patch` otherwise, as one imperative sentence (``Implement `Accordion` component``).
- Tests import by relative path (`../../src/utils/mergeSlots`); the `@/` alias doesn't resolve in vitest.
- Keep comments minimal: short JSDoc on public props (with `@default` when there is one), a component doc with `@example`, and a `/** */` comment only where the code isn't self-explanatory.
- New icons: add a 24×24 Unicons-style SVG to `packages/icons/src`; its `index.ts` is generated by `generate.js` on build.

## Components

- Build on Base UI. Name parts after the W3C APG pattern and common design systems, not Base UI's internals, and fold parts consumers never touch into their parent (`AccordionHeader` renders the trigger button).
- One folder per component with `component.tsx`, `index.ts` (`export * from './component';`) and `styles.css` imported by the component. Register it in `providers/ConfigProvider.components.ts` and export it from `components/index.ts`, alphabetically.
- Shape:
  ```tsx
  export interface XOverrides {}
  export type XOwnProps = {};
  export type XBaseProps = ElementBaseProps<'div', XOwnProps>;
  export type XProps = OverridableType<XBaseProps, XOverrides, never>;
  export const X = (props: XProps) => {
    const { ...rest } = useConfig('X', props);
  };
  X.displayName = 'X';
  ```
- Keep the API minimal: add only what is needed now, and put the main content in `children`.
- Name value callbacks `onChange` (map Base UI's `onValueChange` to it).
- Make a part a separate component when consumers compose, reorder or repeat it, or it has its own state or semantics; otherwise expose it as a slot.
- Slots are `slots?: { name?: PartProps }`, rendered with kit components (`Typography`, `Icon`). Name each by what it is and its role (`expandIcon`, `collapseIcon`, `title`). Spread `{...slots?.name}` after the defaults and before props that must stay fixed (`component="span"`).
- `useConfig` resolves `defaultProps`, then the preset, then inline props; `slots` are merged per slot, one level deep, by `mergeSlots`.
- Decorative icons get `aria-hidden`.

## Animation

- JS decides when an element enters or leaves; CSS alone decides how it moves.
  - Base UI parts handle their own presence.
  - Everything else uses `Transition`, never timers or wrapper elements. Its child is one keyed element that forwards `ref` and `data-*`: changing the `key` swaps it (exit, then enter) and `null` or `false` exits it.
    ```tsx
    <Transition>{open ? <Icon key="collapse" name="Minus" /> : <Icon key="expand" name="Plus" />}</Transition>
    ```
  - Both set `[data-starting-style]` and `[data-ending-style]`, and the CSS animates those.
- Write the animation in the CSS of the component that owns the element, on its own class (`.RosenCopyButton > .RosenIcon`), never on the child's generic class (`.RosenIcon`) or on `.RosenTransition`. `Transition` has no styles, so an unstyled child swaps instantly.
- No animation presets, `data-animation` attributes or `animation` props.
- Use only the motion tokens from `components/index.css`, never raw values:
  - `--rosen-motion-duration-short` for small elements such as icons, `-medium` for popups, panels and color changes, `-long` for large surfaces: dialogs, backdrops and toasts.
  - `--rosen-motion-easing-enter` on the base rule with `-exit` under `&[data-ending-style]` for enter and exit; `-standard` for in-place changes such as height or hover.
- Animate the individual `scale`, `rotate` and `translate` properties, not `transform`, and don't position elements with `transform` (Badge still does; don't copy it).
- Reduced motion is handled once in `components/index.css` by zeroing the duration tokens; don't add `prefers-reduced-motion` to components. Apps that override the tokens do it inside `@media (prefers-reduced-motion: no-preference)`.
- `[data-instant] { transition-duration: 0s; }` belongs to Tooltip only; Popover and Menu set `data-instant` too but must keep animating.

## CSS format

- One block per selector, with its states nested inside.
- Motion declarations go last, as longhands on separate lines (no `transition` shorthand), followed by the shared start and end state, then the exit easing:
  ```css
  .RosenCopyButton > .RosenIcon {
    flex-shrink: 0;
    transition-property: opacity, rotate, scale;
    transition-duration: var(--rosen-motion-duration-short);
    transition-timing-function: var(--rosen-motion-easing-enter);

    &[data-starting-style],
    &[data-ending-style] {
      opacity: 0;
      rotate: -90deg;
      scale: 0.5;
    }

    &[data-ending-style] {
      transition-timing-function: var(--rosen-motion-easing-exit);
    }
  }
  ```
